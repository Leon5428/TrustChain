# TrustChain

**面向多智能体协作的可验证动态授权与信任委托系统**

*TrustChain: Verifiable Dynamic Authorization and Trust Delegation for Multi-Agent Systems*

> **项目状态：研究预研阶段（Research & Exploration）**
>
> 本项目拟参加 2027 年全国大学生信息安全竞赛作品赛，致力于研究多智能体协作环境中的密码学授权、权限安全委托与跨框架权限语义一致性问题，并构建兼具理论依据与工程实用性的安全授权系统。

## 1. 项目简介

随着大语言模型（LLM）与智能体（Agent）技术的发展，AI 系统正在由单一智能体执行任务，逐渐转向多个智能体协同完成复杂工作。

在多智能体系统中，任务可能经过多级委托，由不同 Agent 调用外部工具、访问敏感资源或操作第三方服务。然而，现有智能体系统仍面临权限边界不清晰、跨服务授权语义不统一、委托关系难以验证以及授权状态动态变化等安全问题。

传统的提示词约束与基于角色的权限控制，难以单独保证多级委托过程中的权限安全。与此同时，现有数字签名、OAuth 授权及能力令牌机制虽然提供了重要的技术基础，但如何将它们应用于动态、多级、跨框架的 Agent 协作环境，仍存在值得研究的系统性问题。

**TrustChain 旨在探索一种面向多智能体协作的可验证授权机制，使系统能够在明确的信任与安全模型下，对跨 Agent 委托、工具调用与权限边界进行独立验证。**

项目以密码学协议与安全模型为理论基础，以真实多智能体框架和工具调用场景为工程载体，力求在安全性、可验证性、兼容性与系统开销之间取得合理平衡。

## 2. 研究目标

TrustChain 将重点围绕以下四个目标开展研究。

### 2.1 多级授权委托的可验证性

研究 Agent 之间的多级权限委托机制，使委托凭证能够在密码学意义上被验证，并确保委托过程不会扩大原始授权范围。

在明确的授权语义下，多级委托应满足权限单调收缩原则：

`Permissions(Aₙ) ⊆ Permissions(Aₙ₋₁) ⊆ ... ⊆ Permissions(A₀)`

即子 Agent 获得的有效权限不得超过其上级 Agent 所拥有的权限。

### 2.2 跨框架权限语义一致性

这是项目当前优先研究的核心问题。

不同 Agent 框架、MCP Server 和第三方服务可能采用不同的权限表示方式。相同的权限名称在不同系统中未必对应相同的操作能力。

TrustChain 将探索一种形式化的权限描述与验证机制，对不同系统中的资源、操作、参数约束和授权条件进行建模。

目标是在可信权限规范的基础上，验证跨框架权限映射及委托过程中是否存在意外的权限扩大。

### 2.3 动态授权与安全撤销

研究 Agent 在执行长期任务时的授权生命周期管理，包括：

- 授权凭证的有效期与使用范围。
- 委托链中权限的动态变更。
- 授权撤销状态的验证与传播。
- 授权凭证的重放与跨任务复用防护。
- 授权状态不一致时的安全处理策略。

项目将明确在线验证、缓存状态与离线验证的不同安全假设，不预设能够在完全离线条件下实现即时撤销。

### 2.4 独立于大模型行为的安全执行

TrustChain 将研究如何在 Agent 的自然语言推理过程之外，建立独立的授权验证与策略执行机制。

安全决策不应仅依赖 Agent 对自身行为的描述，而应由可信的验证组件根据授权凭证、操作参数、策略约束及当前授权状态做出判断。

## 3. 核心研究问题

项目初步确立以下研究问题（Research Questions）。

| 编号 | 研究问题 |
|---|---|
| RQ1 | 如何形式化描述不同 Agent 框架中的资源、操作和参数级权限？ |
| RQ2 | 如何验证跨框架权限映射及多级委托过程中的权限不扩大性质？ |
| RQ3 | 如何将授权凭证与实际工具调用绑定，防止越权调用和凭证重放？ |
| RQ4 | 如何在动态授权与权限撤销场景中保持可验证的安全边界？ |
| RQ5 | 如何在保证安全性质的前提下降低授权验证带来的通信与计算开销？ |

以上问题是当前阶段的研究假设与技术探索方向，不代表项目已经获得新的密码学研究成果。

最终的核心研究问题将根据文献查新、方案分析和原型实验进一步收敛。

## 4. 初步威胁模型

TrustChain 主要考虑具有复杂工具调用和多级权限委托关系的智能体系统。

### 4.1 潜在攻击者

攻击者可能具有以下一种或多种能力：

- 通过恶意提示词或外部数据影响 Agent 的决策。
- 控制部分参与协作的 Agent。
- 获取、重放或篡改部分授权消息。
- 利用不同服务对权限含义的解释差异。
- 尝试通过多级委托扩大可执行操作范围。
- 在权限变更或撤销过程中利用过期授权状态。

### 4.2 基本信任假设

初步假定用户授权中心、可信策略执行点及必要的密钥保护机制能够正常工作。

被控制的 Agent 不应直接拥有修改可信授权策略或绕过验证网关的能力。

对于工具提供方提供的权限规范、能力描述及其更新机制，项目将进一步定义来源真实性和可信边界。

### 4.3 预期安全性质

项目拟研究并验证以下性质：

1. **授权真实性**：授权凭证可验证其签发主体与完整性。
2. **委托安全性**：有效委托不会扩大原始权限范围。
3. **操作约束性**：实际工具调用满足对应资源、动作与参数约束。
4. **上下文绑定性**：授权凭证不能被任意跨任务或跨服务复用。
5. **撤销有效性**：在指定的新鲜度与同步假设下，已撤销授权不会继续被接受。
6. **失败安全性**：权限映射存在歧义或必要验证失败时，执行点采取拒绝策略。

上述性质的成立范围取决于最终协议设计及威胁模型，需要通过形式化分析和实验进行验证。

## 5. 拟议系统架构

TrustChain 计划采用分层架构，将智能体任务执行与可信授权验证相分离。

整体流程如下：

**用户授权 → 授权凭证签发 → 多级 Agent 委托 → 权限语义映射 → 委托链验证 → 操作授权判定 → 工具执行 → 安全审计**

系统拟包含以下核心组件：

| 组件 | 主要职责 |
|---|---|
| Authorization Authority | 管理授权主体、策略及凭证签发 |
| Delegation Manager | 管理多级委托关系和权限收缩 |
| Permission Semantics Engine | 描述并验证跨框架权限语义及映射 |
| Cryptographic Verifier | 验证授权凭证、签名与委托关系 |
| Policy Enforcement Gateway | 对工具调用实施独立授权检查 |
| Revocation Manager | 管理授权生命周期及撤销状态 |
| Audit & Evaluation | 记录验证证据并支持安全实验 |

上述组件属于拟议架构，实际实现形式将依据核心协议研究结果调整。

## 6. 技术研究路线

### 6.1 密码学基础

项目计划研究并评估以下技术：

- 数字签名与密码学哈希函数。
- 能力令牌（Capability Token）。
- 基于密码学凭证的权限委托。
- OAuth 2.0 Token Exchange。
- 细粒度授权与请求绑定机制。
- 授权链验证及撤销状态认证。

具体算法、凭证结构和协议组合尚未最终确定。

### 6.2 形式化安全分析

项目计划为核心协议建立明确的安全模型，并在适用范围内使用 Tamarin Prover 等工具分析协议安全性质。

形式化验证将重点考虑授权链完整性、权限收缩、重放攻击与攻击者控制部分 Agent 的情况。

### 6.3 多智能体工程集成

计划研究与以下生态的集成：

- Model Context Protocol（MCP）
- Agent2Agent Protocol（A2A）
- 主流开源多智能体框架
- GitHub、数据库、文件系统等典型工具服务

项目将优先建设隔离的实验环境，避免真实高权限工具调用造成不可逆影响。

## 7. 预期实验与评估

为验证方案的实际价值，TrustChain 计划建立可复现的实验体系。

### 安全性评估

主要考虑多级委托越权、跨框架权限混淆、请求参数替换、凭证重放、授权撤销延迟以及部分 Agent 被攻陷等场景。

### 性能评估

拟测量：

- 授权凭证生成与验证时间。
- 不同委托深度下的验证开销。
- 授权链长度与凭证大小。
- 跨框架权限映射开销。
- 授权撤销传播延迟。
- 端到端任务执行延迟及吞吐量。

### 对照与消融实验

计划与标准 OAuth 授权、现有能力委托方案及相关开源实现进行适当对照。

通过移除或替换独立安全机制，分析其对系统安全性与性能的具体影响。

所有实验结果均应提供清晰的实验条件、基线版本、数据来源与复现步骤。

## 9. 持续研究与文献跟踪

多智能体授权是快速发展的研究方向。

TrustChain 将持续跟踪密码学研究、身份授权标准、多智能体通信协议和安全工程实践。

重点关注：

- IACR ePrint 和 arXiv 上的相关研究。
- IETF OAuth、WIMSE 等工作组及相关草案。
- MCP 与 A2A 协议规范的更新。
- 开源 Agent 安全框架及授权实现。
- 多智能体协作场景中的新型攻击与安全评测。

项目将定期检查现有研究是否覆盖候选创新点，并在必要时调整研究重点。

目前优先关注的技术问题是：

**跨框架权限语义的一致性建模与可验证安全委托。**

该方向仍需通过系统性文献查新确认具体创新空间。

## 12. 项目愿景

TrustChain 希望探索多智能体系统安全从基于提示词的行为约束，走向具有明确安全模型、密码学凭证和可信执行边界的可验证授权机制。

项目的最终目标不仅是实现一个多智能体安全系统，更是通过严谨的理论分析与真实的工程实验，研究多级授权与跨框架协作中具有实际价值的安全问题。
